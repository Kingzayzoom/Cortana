# Implementation and limits

The project was empty except for `Samantha visualization.png`. Its image was inspected and the UI rebuilt with actual components; it is not embedded as the dashboard or orb. Next.js App Router, React 19.2, TypeScript, Tailwind 4, customized shadcn-style Radix primitives, Lucide, the official ElevenLabs React SDK, and the official ElevenLabs UI orb form the implementation.

The orb registry at `ui.elevenlabs.io` returned HTTP 429. The exact official registry artifact was fetched from `elevenlabs/ui` on GitHub, saved under `vendor/orb.registry.json`, and installed with `npx shadcn@latest add ./vendor/orb.registry.json --yes`. The upstream MIT license is preserved. The registry's React Three Fiber dependency requires React below 19.3, so React 19.2.8 is pinned rather than bypassing peer checks.

The official source has a flat two-color polar finish; it lacks spherical surface normals, specular depth, and a third palette color. Those concrete limitations prevent the supplied translucent reference/ShaderGradient material. The adaptation retains the official renderer, its noise and flow foundation, and adds a sphere-normal material finish, curved flowing ribbons, a narrow bright edge and elongated highlight. Colors take inspiration from `#7896d6`, `#ff14b9`, and `#af38ff`, with cyan mixed in to preserve the clinical reference. It is a live shader, not an image or video. A locally served upstream noise texture is a shader input, not the orb itself.

Production callers use manual audio refs exclusively. Actual ElevenLabs input/output getters feed a ref-based frame loop with a 65ms attack, 240ms release, 0.015 noise floor and clamping. Input is suppressed when muted or disconnected; output is independent. Audio controls modest scaling, flow, distortion and the halo. No production code invents speech activity. Ambient idle movement is intentional. DPR is capped at 1.5, hidden tabs stop continuous rendering, and reduced motion freezes the surface. WebGL failure gets a visibly labeled lightweight fallback. Renderer, listeners, timers and animation frames are disposed on unmount.

In the installed R3F 9.7 development build, React StrictMode remounting disposed the active render root and left the canvas empty. Development StrictMode is disabled in `next.config.ts`; explicit lifecycle cleanup and mounted/unmounted behavior are covered by browser tests. The upstream dependency emits a Three.Clock deprecation warning. No application page errors were observed in the passing browser navigation test.

Connection state, voice activity and lesson checkpoints are separate. A stable root ConversationProvider survives navigation and evidence drawers. The SDK manages audio capture. Message IDs deduplicate final transcripts; provisional output is not graded. Mute calls the supported `setMuted`. Live Pause is hidden because this SDK has no native pause/resume API. Text preview retains its checkpoint pause. End waits for SDK disconnection; reconnect uses a new temporary token. A connection timeout and a teardown timeout prevent indefinite status spinners. A still-pending browser microphone prompt must be resolved before another SDK start can run. Late tools are scoped to their connection generation and run ID.

The storage adapter writes per-profile JSON files with serialized operations and atomic replacement in `.cortana/`. Signed HttpOnly cookies isolate profiles. This is a single-server demo adapter, not browser localStorage, multi-node database transactions or cloud synchronization. The application tells users where their progress lives. Clearing cookies loses access to that local demo profile; Settings offers a deliberate reset for the active profile.

Content is a versioned DAPA-HF teaching bundle with one fixed question and two linked primary publications. Source checks are not an independent clinical review. The evidence does not support patient-specific prescribing, and the app provides none. Practice counts are not mastery scores. No fabricated history, accreditation, regulatory approval, or clinical-outcome claims are used.

The corrected secret and updated Write permission successfully mint real WebRTC tokens. Full Chromium (headed) connected to the actual Samantha agent with a physical microphone, received provider speech and final transcripts, measured separate input/output energy, muted the microphone, released all microphone tracks and peer connections on End, and reconnected with one live microphone. Headless Chromium on this machine rejects physical microphone capture with `NotSupportedError`; the app now explains that condition. No fake media device was used in those successful tests.

The existing account model `qwen35-397b-a17b` and voice were preserved. Seven Client tools, the versioned DAPA-HF knowledge document, the learning prompt, interruption/VAD events, and checkpoint dynamic variables are now attached. The prior account configuration and applied patch are backed up under ignored `.cortana/`. Provider tool schemas require parameter descriptions and reject `additionalProperties`; the export adapts to that subset while the app retains full strict Zod validation. A first rehearsal revealed long pauses between sections, so the prompt now explicitly requests a continuous briefing and the Continue control requests the next section rather than restarting the current one. Deliberate spoken interruption timing remains a manual rehearsal item.

## Installed SDK contract

The installed `@elevenlabs/react` is 1.15.2. Its `startSession` and `endSession` control functions return `void`, despite a promise-returning example still present in the public docs. The controller uses `onConnect({ conversationId })`, status changes and disconnection callbacks. `setMuted` throws before a conversation exists; unmute initialization is therefore deferred until `onConnect`. The token endpoint validates both `token` and `conversation_id`, returns `{ token, conversationId }`, and never caches success or errors. The browser passes `conversationToken` and `connectionType: "webrtc"` to the SDK. The token is fetched before SDK-managed microphone permission: the SDK requires a credential to start its own capture flow, so there is no separate preflight microphone stream.

Live transcript state belongs to the voice controller. Final message event IDs deduplicate events; agent corrections replace the existing row. Typed messages and matching server echoes share a row. Local preview transcript state remains explicitly separate in the learning provider. Generation guards reject late callbacks and client tools after End or reconnection. The orb still uses the original renderer and refs; numeric input/output data attributes support measurement without introducing generated audio.

The voice tool contracts omit requestId. During real-provider rehearsal the model generated non-hexadecimal UUIDs, which the app correctly rejected. The controller now creates a UUID for each validated run/operation/payload and reuses it for identical retries before forwarding to the strict server API.
